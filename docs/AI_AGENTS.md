# AI_AGENTS.md — how coding agents use Platform V2

Read `WORKFLOW.md` first. This file defines roles and the harness-specific mechanics; it does not
repeat the workflow. Canonical agent definitions live in `.claude/agents/*.md`; Codex and Antigravity
copies are generated by `python scripts/sync_agents.py` (`.codex/agents/*.toml`,
`.agents/agents_staging/*.md`). Capability tiers map to models in `config/agent_model_profiles.json`.

## Shared roles (model-agnostic)

| Role | Owns | Writes | Tier |
|---|---|---|---|
| **Primary owner** (the interactive session) | the task, integration, normal implementation, running the controller | code, docs, study YAML | capable mid-tier |
| **Repo scout** (`repo-scout`) | bounded read-only discovery: where is the authoritative implementation, what is in a closure | a compact evidence packet | cheap / read-only |
| **Causal auditor** (`lookahead-auditor`) | independent read-only audit of timestamps, availability, OOS and target causality from `_work/controller/audit_packet_causal.json` | `studies/<id>/audit/pass_NN.md` only | governance review |
| **Contract auditor** (`contract-checker`) | independent read-only audit of compiled contracts, artifacts, chronology, closure integrity from `audit_packet_contract.json` | `studies/<id>/audit/contract_pass_NN.md` only | governance review |
| **Test runner** | deterministic: `python -m pytest <files> -q`, `research cap generate --check`, controller stages — a script, not a model | — | none (scripts) |
| **Results triager** (`results-triager`) | reads compact artifacts (test logs, parity reports, cards) and separates new regressions from the classified baseline | a short triage card | cheap / read-only |
| **Frontier architect** (the primary session on a frontier model, e.g. Claude Fable) | ONLY new semantic primitives, ambiguous causal interpretation, architecture gaps, novel platform design | platform code + docs | frontier |

Rules:

* **One writing agent = one study worktree**, enforced by the writer lease (`user@host` + agent + session).
  `research study new` creates the worktree and records the writer; `research ws claim <id>` re-enters it; a live lease of
  another agent is refused (`STUDY_WORKTREE_OWNED_BY_ANOTHER_AGENT`). Platform work uses a dedicated `chore/*` worktree.
  Read-only auditors need no claim and may read a worktree while its writer works, as long as nothing they read is being mutated.
* The primary owner does not delegate routine implementation; there is no implementer swarm.
  `implementer` exists for one bounded repair packet at a time.
* Deterministic work goes to scripts and the controller. Do not poll long jobs by hand: launch detached
  (`nohup python -u ... & disown`), then re-run the same controller command to resume.
* Auditors read packets, not the repository; they end their report with the `AUDIT_SUMMARY_V2` block and
  never write `status.json` (the controller ingests it via `research audit ingest`).
* Every agent returns a compact card (STATUS, state, blocker_code, artifact), never a narrative.
* A typed `CapabilityGap` is the only sanctioned way to say "the platform cannot express this".

Roles that deliberately do not exist: a "study driver writer", a "collector author", a "manual OOS opener".

## Starting a research project (every primary coding agent)

1. Read `WORKFLOW.md`, then its §M **Concurrent research projects**.
2. **Identify yourself**: `python scripts/research.py ws whoami` must show your agent (`claude` / `codex` / `antigravity`) and a session id. If it does not, the launcher is missing `NT_RESEARCH_AGENT` / `NT_RESEARCH_AGENT_SESSION` (see *Writer identity* below); fix that before writing anything.
3. Confirm a clean source `main` on the canonical checkout: `git switch main && git status --short`.
4. Create the study with the CLI: `python scripts/research.py study new <id>` -- this records your agent/session as the study's writer.
5. `cd` into the generated worktree named in the card (`../<repo-name>-<id>`).
6. Do ALL writes there; never write from `main`.
7. **Resuming an existing study**: `python scripts/research.py ws claim <id>` before any write. Same agent/session -> idempotent. A `live` lease held by another agent or session -> `STUDY_WORKTREE_OWNED_BY_ANOTHER_AGENT`: stop, take another study or wait; never edit lease files, never "take over" because the OS user matches. `stale`/`released` leases are claimable; `dead` ones are cleared with `ws list --reclaim`.
8. Never share that worktree with another writing agent.
9. Execute the study through the controller (`python scripts/run_governed_study.py --study studies/<id> --through <stage> --execute-authorized`), never by hand. The controller re-checks the writer lease (who may edit) and then its own run lock (is a run already live); both must pass.
10. Platform modifications belong on a separate `chore/*` worktree, never in the study branch.
11. **Read-only roles** (repo-scout, lookahead-auditor, contract-checker, results-triager, capability-router, Explore) skip steps 2-8: they need no writer claim, may inspect source, artifacts, audit packets and results in any worktree, and mutate nothing but their own audit report.

Three mechanisms, all independent, all required: **branch/worktree isolation** prevents cross-study
file conflicts; the **writer lease** prevents cross-agent ownership conflicts; the **controller run
lock** prevents duplicate study execution.

### Writer identity

`research_workflow.workspace.writer_identity()` resolves `user@host` + agent + session id in this order:

| precedence | source | Claude Code | Codex | Antigravity |
|---|---|---|---|---|
| 1 | launcher env `NT_RESEARCH_AGENT`, `NT_RESEARCH_AGENT_SESSION` | optional | `NT_RESEARCH_AGENT=codex` is set by `.codex/config.toml` (`shell_environment_policy`); set `NT_RESEARCH_AGENT_SESSION=<uuid>` per session in the launcher | **`scripts\launch_antigravity.cmd -Study <id>`** sets both with a fresh UUID per launched instance (Antigravity IDE is a VS Code fork with no native agent/session variable and is single-instance; see `.agents/AGENT_WORKFLOW.md`) |
| 2 | harness-native env | inferred automatically: `CLAUDECODE` -> agent `claude`, `CLAUDE_CODE_SESSION_ID` -> session | `CODEX_SANDBOX*` / `CODEX_THREAD_ID` | none: Antigravity IDE exports only `TERM_PROGRAM=vscode` / `VSCODE_*` |
| 3 | process-tree anchor | the harness process at the top of the shell's ancestry (`name:pid:create_time`) -- stable for one interactive session | same | agent label `antigravity` is inferred from `antigravity ide.exe` in the ancestry, but all windows of one instance share the anchor -- only the launcher UUID separates sessions |

Values are recorded on the lease as `owner_agent` / `owner_session_id`, shown by `ws list` and
`ws whoami`. A session id is never a bare PID of the calling shell.

**Fail closed on ambiguous identity.** A write-capable agent asserts who it is: `ws whoami --expect <agent>`,
`study new <id> --as <agent>`, `ws claim <id> --as <agent>`. If the shell resolves as `human`/unknown the
command fails with `WRITER_IDENTITY_AMBIGUOUS`; if it resolves as a different agent, `WRITER_IDENTITY_MISMATCH`.
Neither creates or claims anything. A human researcher at a terminal simply omits `--as`.

**DO NOT manually create a study branch or worktree when the Platform V2 CLI can do it.** The CLI is
the canonical path because it also establishes the skeleton, the writer lease, the ownership metadata
and the expected branch naming (`study/<id>`).

Recommended use: the primary Claude session owns implementation and runs the controller; spawn
`repo-scout` for discovery, one `lookahead-auditor` and one `contract-checker` per study (continue the
same agent for delta passes so context is kept), `results-triager` after a full test run. Model tiers:
frontier for semantic architecture only; capable mid-tier for normal coding and research workflow;
cheap read-only for scouting and triage. Pricing is not encoded anywhere; tiers are in
`config/agent_model_profiles.json`.

Claude-specific manual: `CLAUDE.md` (read after `WORKFLOW.md`).

## Gemini (Gemini CLI / coding agent)

Gemini CLI reads `GEMINI.md` at the repository root; `.agents/agents_staging/*.md` are the generated
role bodies for Antigravity. Gemini should:

1. read `WORKFLOW.md`, then `docs/QUICKSTART.md`;
2. use `python scripts/research.py ...` for every platform operation (never reimplement orchestration);
3. never write study Python; express missing capability as a typed `CapabilityGap` (compile) and, if
   needed, a proposal via `research cap propose`;
4. work in the study's own worktree (`research study new`), launched through `scripts\launch_antigravity.cmd -Study <id>`; before any write run `python scripts/research.py ws whoami --expect antigravity` and stop on anything but `STATUS: OK` (`WRITER_IDENTITY_AMBIGUOUS` / `WRITER_IDENTITY_MISMATCH`); claim with `ws claim <id> --as antigravity`;
5. request audits by handing the packet paths to the auditor roles and ingest with `research audit ingest`;
6. return compact cards.

No unsupported Gemini features are assumed; if a mechanism is missing on your Gemini version, use the CLI directly.

## Codex (OpenAI Codex)

Codex reads `AGENTS.md` and `CODEX.md`; `.codex/agents/*.toml` hold the generated role instructions and
`.codex/config.toml` the harness settings. Codex should act as a bounded primary owner: explore with
`repo-scout` or `rg`, implement the one packet it was given, run the targeted tests, use the study's
worktree, drive stages with `scripts/run_governed_study.py`, hand audit packets to the auditor roles, and
never poll long jobs manually (detach, then resume with the same command). Use Platform V2 rather than
re-creating orchestration in prompts.
