# Subagent Roster — Rationale

Companion to `AGENTS.md` §11, which holds the roster table, the shared audit protocol and the
coordination rules. This file explains *why* the set is what it is — including the roles that
deliberately do not exist.

`.claude/agents/*.md` is the **canonical** source. `.agents/agents_staging/*.md` and
`.codex/agents/*.toml` are generated by `python scripts/sync_agents.py`. Do not hand-edit the
generated files. Every agent is now generated for every harness; there are no harness-only
agents apart from the `Explore` model pin.

---

## Six roles, one model pin

| Agent | Column it owns |
|---|---|
| `repo-scout` | *Where is it, and where does a change belong?* |
| `lookahead-auditor` | *Could this be known at T?* |
| `contract-checker` | *Does this match what was declared, and is the lifecycle state legitimate?* |
| `implementer` | *Make it correct.* |
| `research-executor` | *Run the lifecycle and produce the artifacts.* |
| `analysis-decider` | *What does this mean, and what do we do next?* |
| `Explore` | not a role — a model pin (below) |

Ownership is exclusive. An agent that finds work in another column refers it in one line and
moves on.

---

## Why the two auditors are not merged

A single "causality / governance auditor" is the obvious simplification. It is blocked by
tooling, not by preference.

`scripts/run_preexec_audits.py` enforces `AUDITOR_ROLE_REUSE`: the causal and contract reviews
must be authored by **distinct declared reviewer identities**. One agent filing both reports is
"a one-reviewer workflow wearing a two-reviewer seal", and the seal is refused. That check
exists because a single report once satisfied both mandatory gates and the seal named two
reviewers that never existed.

The evidence behind the split is also concrete: across ~100 historical audit reports, ~60% of
blocking findings were *completeness* (`D1` 22, `C4` 22, `C3` 12, `D4` 9) rather than
look-ahead. The causal checklist has no natural stopping point for completeness, so a combined
auditor invents findings each pass — one study ran **18 passes**. Disjoint, enforced scope plus
the bounded re-audit protocol is what stopped it.

Together the two agents cover exactly one conceptual role: **causality and governance**. They
are two files for a mechanical reason.

## Why `Explore` stays

`Explore` is a **built-in** agent. Without a project-level definition it inherits the
orchestrator's model, which here is Opus — so a routine "where is X defined?" sweep would run at
orchestrator cost. `.claude/agents/Explore.md` exists solely to pin it to Haiku.

It is not a competing role. For evidence that feeds a SPEC, a plan, or an audit, use
`repo-scout`. Deleting `Explore.md` silently restores Opus-cost discovery.

## Why there is no performance / benchmark agent

Decided from actual repo usage, not preference. The benchmarking capability is already
deterministic and already exists:

- `scripts/benchmark_historical_same_harness.py` — historical controls through the canonical
  data-plan/engine builder
- `scripts/run_collector_ablation_matrix.py` — ablation on one replay day
- `backtests/nt_runtime/telemetry.py` — opt-in `tracemalloc`, always-on RSS

The one durable lesson — telemetry must not materially alter execution performance, and
instrumentation cost must be separated from replay cost — is a **rule**
(`docs/RESEARCH_WORKFLOW.md` §7) and a **measurement**
(`docs/WORKFLOW_REFERENCE_FACTS.md`). An agent would re-run those scripts and paraphrase the
numbers, adding a second, weaker source of truth for a figure that is already reproducible.

If a profiling campaign ever needs sustained judgement rather than script invocation, this is
the role to add, and `research-executor` is the wrong home for it.

## What changed in the 2026-08 redesign

| Agent | Action | Reason |
|---|---|---|
| `repo-scout` | kept, sharpened | Already the architecture-scout role; gained explicit execution-closure tracing and stale-path detection |
| `lookahead-auditor` | kept, trimmed | Shared audit protocol moved to `AGENTS.md`; card fell 199 → 115 lines |
| `contract-checker` | kept, trimmed | Same; card fell 208 → 126 lines. Governance ownership (TRAIN/OOS, authorization, freeze/seal, provenance) made explicit |
| `implementer` | **added** | Was Codex-only `implementation-worker`; now a first-class role on every harness |
| `research-executor` | **added** | Lifecycle execution had no owner; the orchestrator was doing it inline |
| `analysis-decider` | **added** | Result interpretation had no owner |
| `results-triager` | **removed** | Its whole job — run targeted tests, reduce output — is `implementer`'s. Two agents owning test execution violates exclusive ownership. For a one-off test run the orchestrator uses Bash directly rather than paying for an agent |
| `implementation-worker` | **retired** | Superseded by `implementer`, which is generated for all three harnesses instead of existing only under Codex |

`validate-results-triager-command.py` (both harnesses) was deleted with the agent it guarded —
it was scoped by name to `results-triager` and enforced nothing once that agent was gone.
`.codex/hooks/deny-subagent-tool.py` is **kept**: it is generic, denying a tool call for any
bounded subagent, and is not tied to a removed role.

## Principles every subagent inherits

Stated once in `AGENTS.md` — §6 (autonomy), § Shared subagent principles, § Shared audit
protocol. Agent cards reference them and must not restate them differently.

The rule that matters most: **a failed gate means do not advance; it does not mean terminal
stop.** The six terminal-stop conditions are enumerated in `AGENTS.md` §6 and nowhere else —
a second list drifts from the first.

Each card states only: role · scope · inputs · workflow pointer · must-do · must-not-do ·
output contract · escalation. No card copies `docs/RESEARCH_WORKFLOW.md`.

---

## Changing this roster

Adding, removing or re-tiering an agent is a framework change. It needs the escalation
justification in `docs/RESEARCH_WORKFLOW.md` §1, an update to `AGENTS.md` §11 and to this file,
a `CODEX_META` entry in `scripts/sync_agents.py`, and `python scripts/sync_agents.py` — all in
the same change. `scripts/tests/test_agent_sync_metadata.py` is parameterized over `CODEX_META`
and will cover the new agent automatically.
