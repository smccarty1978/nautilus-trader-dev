A. Executive verdict

What the framework actually guarantees today

The architecture is sound and several controls are genuinely load-bearing — the compiled-study staleness hash, the prohibited-year guard, the OOS dev-year lock, the ordered feature-list + SHA enforcement, and the seal-before-catalog call ordering all fail closed exactly as designed, and I could not break them. That part of the brief's "what good looks like" list is real.

The failures cluster in one place: the perimeter of what is sealed, linted, and independently audited is much narrower than the documents assert, and nothing in the system measures its own coverage. The seal covers 36 files and omits the single most causally load-bearing module in the repository. The causal lint scanned exactly one file — a test file. The "independent audit" is a Python function that writes whatever verdict its caller passes as an argument. Each of these is invisible from the inside, because every gate reports on what it checked, never on what it skipped.

Consequence: the four green stamps on the current study (preflight CLEAR, status.json CLEAR, contract_status.json CLEAR, PREEXEC_AUDIT_SEAL_VALID) do not, individually or together, establish that the audited code is causal — and F3 below shows a concrete case where they were wrong.

Do not read this as "add more gates." The count of controls is already high; the problem is that several of them have zero or near-zero effective scope, and one is a no-op that returns its own input. Section F recommends deleting two checks outright.

CriticalF1

The seal omits the causal-ordering helper, the seal verifier, and its caller

scripts/preexec_audit_seal.py:33–51 (CRITICAL_REPO_PATHS), :232–257 (verify_preexec_audit_seal)
Mechanism
The composite hash is built from a hardcoded 17-path list. Missing: utils/causal_registration.py (the only thing enforcing 1s-before-1m), backtests/nt_runtime/modes/collect.py (the file that calls verify_preexec_audit_seal), scripts/preexec_audit_seal.py itself, utils/runner/data.py, compiled_study_loader.py, strategy_binding.py, run_nt_study.py, and features/engine.py. Verification iterates only file_hashes, so an unlisted file is invisible by construction.
Failure
Demonstrated above: three tampered files, PREEXEC_AUDIT_SEAL_VALID, and the seal regenerates cleanly. An inverted registration order silently reintroduces the MFE/MAE blind spot that CLAUDE.md invariant #4 exists to prevent.

No control measures the seal's own coverage, and the guard tests never modify a source file (see F5).
Fix
Derive the repo set from the compiled contract instead of a literal list: seal every module transitively imported by modes/collect.py plus every bound_trackers entry in feature_contract, and always include the seal module itself. Make an unresolvable import a hard error, not a silent omission.

CriticalF2

Audit provenance is self-issued — no independent auditor is ever invoked

scripts/run_preexec_audits.py:22–75, :78–130
Mechanism
The module contains two functions and nothing else — no main(), no CLI, no subprocess, no agent call. verdict, critical, and warning are caller parameters; auditor="lookahead_auditor" is a default string literal. It hashes a Markdown file the caller wrote. The brief states this script "must never substitute 'write CLEAR JSON' for a real auditor invocation" — writing CLEAR JSON is the entirety of what it does.
Failure

Why missed
The seal validates provenance structure (version, hash binding, verdict counts) and every field is genuinely well-formed. Nothing distinguishes an auditor-authored report from an implementer-authored one.
Fix
Independence cannot be proven cryptographically by the party being audited; stop implying it is. Either (a) record the actual subagent transcript hash and invoking session id and have the seal require them, or (b) rename the artifacts to self_attested_* and drop "independent" from the docs. Option (b) is honest and costs nothing; (a) is the real fix.

CriticalF3

30 of 2,032 rows in the sealed fixture are priced one second after their own observation timestamp

strategies/flip_prediction_collector.py:386–394, :482, :604, :609
Mechanism
The checkpoint loop fires for every T = regime_start + (k+1)·5s with T ≤ ts_init of the current 1s bar, and prices it with that bar's close (price_at_T=c) while stamping observation_ts = T (:604). The base-25 windows use a third anchor, obs_ts = ot.ts[-1] (:482) — the latest 1s bar, not T. The 1s stream is not gapless: seconds with no trade produce no bar, so whenever T lands in a gap the loop catches up on the next bar and back-stamps future data onto T.
Failure
Measured directly against the catalog and the sealed fixture run:
2023-03-03 RTH: 22,955 1s bars / 23,400 seconds → 445 seconds missing gap sizes(s): {1: 22531, 2: 402, 3: 20, 4: 1} fixture candidates.parquet (2,032 rows, 72 cols): evaluated with a 1s bar exactly at T : 2002 evaluated LATE (trigger ts_init > T) : 30 (1.48% of population) lateness histogram : {1.0s: 30} e.g. observation_ts 2023-03-03 16:55:30Z close 12217.75 ← sourced from 16:55:31Z
Affected columns include close, price_change_atr_30s/60s, every *_signed_distance_atr, and pct_levels_behind_trade. This violates the framework's own canonical form, latest_source_ts_init <= observation_ts.
Why missed
Three reasons compounding. The lint never opened the file (F4). The bias is conditional on a data gap, so it is invisible in any code reading that assumes a dense 1s stream. And the compiled contract asserts the cadence is 1m_bar_close (F9), so an auditor checking the contract would not look for a 5s-grid/1s-arrival mismatch at all.
Fix
Smallest correct change: in _evaluate_checkpoint, skip any checkpoint where the triggering bar's ts_init != T, or emit it with observation_ts = ts_init and an explicit checkpoint_late_seconds column. Do not interpolate. Given the 0.5 progress floor and MFE gates already applied, dropping ~1.5% of rows is the cheaper and more defensible option.
Regression test
test_no_candidate_sourced_after_observation_ts — replay the fixture day, assert for every emitted row that the triggering bar's ts_init equals observation_ts. It fails today at 30 rows.
