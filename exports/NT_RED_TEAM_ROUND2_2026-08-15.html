Executive verdict

Where the remediation genuinely moved the needle — and where it only appears to

The causal work is excellent. F3 — the look-ahead violation I measured inside the sealed fixture — is fixed properly, at the right layer, and I verified it end-to-end: a fresh collection run produces 2,002 candidates against the previous 2,032, exactly the 30-row drop I predicted, with zero rows now sourced from a later bar. F4 is fixed the right way too: the causal lint is now manifest-driven and reports 31/31 files, 100.0% coverage, and fails closed when coverage is incomplete. Two dead scripts were deleted as recommended. That is real, verifiable engineering.

The governance work has a consistent failure signature. Each control was repaired to satisfy the specific examples in my report rather than the property the example illustrated. Three independent instances:

  • The seal's file list was expanded to include the eight files I named — but it is still a hardcoded list, and two other files in the entrypoint's real import closure remain unsealed.
  • The new module is called resolve_execution_manifest.py, its docstring promises "full transitive closure … entrypoint import closure", and it imports ast and importlib.util. It uses neither. It is two literal lists.
  • The new test test_seal_covers_full_import_closure() computes no closure. It asserts that seven hardcoded keys — the seven filenames from my report — are present, plus len(file_hashes) >= 35. It passes today while the closure is demonstrably incomplete.

The consequence is concrete rather than theoretical: the OOS lock — the one control that survived round 1 intact — is now bypassable, because scripts/generate_oos_unlock.py holds verify_oos_unlock_token(), sits in data_plan.py's import path, and is not in the seal. I opened 2024 with no unlock token while the seal reported VALID and preflight reported CLEAR.

The single highest-value change now is one line of test code. Replace the seven hardcoded keys in test_seal_covers_full_import_closure with an actual AST walk of collect.py's import graph, asserted as a subset of the manifest. That test fails immediately on today's tree and names both missing files. It is the invariant the whole seal depends on, and it is currently asserted by a checklist.

CriticalN1

The new smoke gate reads a key the seal does not have, silently disabling its own staleness binding

backtests/nt_runtime/modes/collect.py:52–57  ·  scripts/preexec_audit_seal.py:159
Mechanism
The gate does seal_data.get("composite_sha256"), but verify_preexec_audit_seal() returns the seal file, whose key is composite_seal_hash. composite_sha256 is the key on manifest_data from the resolver — a different dict. So seal_sha is always None, and the guard (seal_sha and sacc.get(...) != seal_sha) short-circuits to False. Only status == "ACCEPTED" is ever evaluated.
Failure
Verified end-to-end: --stage full with an acceptance naming "0000_STALE_HASH_FROM_PRE_REMEDIATION_CODE_0000" passed both the smoke gate and the seal gate and reached engine construction. A smoke run from any prior code version authorizes a full run on today's code — precisely the chain the brief says must break.
Why missed
The and short-circuit makes the mistake fail open rather than raise. No test covers the gate; the file it needs did not exist when the code was written.
Fix
seal_sha = seal_data["composite_seal_hash"] — subscript, not .get(), so a future rename raises instead of disabling the check. Then compare unconditionally rather than behind seal_sha and ….
Regression test
test_full_stage_rejects_stale_smoke_acceptance — write an acceptance with a wrong hash, assert SMOKE_ACCEPTANCE_STALE.

WarningN5

Dynamic strategy resolution builds an impossible path and silently skips it

scripts/resolve_execution_manifest.py:129–141
Mechanism
The resolver reads spec.execution.strategy_class — which is a dotted path, "strategies.flip_prediction_collector.FlipPredictionCollector" — and interpolates it as f"strategies/{strat_class}.py", producing strategies/strategies.flip_prediction_collector.FlipPredictionCollector.py. That never exists, and the loop guards with if sfp.exists(), so it is dropped without a word. The manifest only contains the collector because line 129 hardcodes it.
Failure
Any study using a different strategy class gets its strategy silently excluded from the seal. Note the asymmetry: governance and runtime entries raise FileNotFoundError when absent, but strategy resolution fails open.
Fix
Split the dotted path (strat_class.rsplit(".", 1)[0].replace(".", "/") + ".py") and raise when the resolved file is missing, matching the other two categories.
Regression test
test_manifest_resolves_non_default_strategy — compile a study naming another strategy, assert it appears in file_hashes.
