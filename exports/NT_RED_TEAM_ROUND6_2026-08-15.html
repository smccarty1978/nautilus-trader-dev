Findings

One new warning, three carried forward

WarningR6-1

Producer and gate read the same config key with opposite defaults, leaving one check inert

backtests/nt_runtime/modes/collect.py:119–124  ·  scripts/validate_smoke.py:171  ·  studies/<s>/study.yaml
Mechanism
Both sides key off execution.observation_policy.required_source_relation. The validator reads it as obs_policy.get("required_source_relation", "equal") — defaulting to strict. The gate reads it as if obs_pol.get("required_source_relation") == "equal": — requiring it to be set explicitly. The key is absent from study.yaml and resolves to None in the compiled contract, so obs_pol is {}, the condition is false, and the enclosed assertion never evaluates.
Failure
Demonstrated: an acceptance with exact_timestamp_equality_verified: False passes the gate. That combination is one the honest validator can never emit — it sets the flag as bool(future_source_violations_count == 0) — so the gate accepts a self-contradictory artifact.
Severity
Warning, not critical. Check 7 enforces future_source_violations_count != 0 unconditionally two lines above, and that is the substantive claim; the inert check is defence in depth on a derived flag. Recorded because the pattern — an optional config key silently deciding whether a safety check applies — is the same shape as R4-1's column-presence guard, and it defaults the wrong way.
Fix
Match the validator's default: obs_pol.get("required_source_relation", "equal") == "equal". Better, add an internal-consistency check independent of config — exact_timestamp_equality_verified must equal future_source_violations_count == 0 — so a contradictory acceptance is rejected on its own terms. Best, declare observation_policy explicitly in study.yaml so neither side has to default.
Regression test
test_gate_rejects_contradictory_acceptance — violations=0 with exact_timestamp_equality_verified=False must raise regardless of observation policy.
WarningR5-2

Preflight still carries a 17-minute market replay and still has no subprocess timeout

scripts/research_preflight.py:162–163  ·  pytest.ini  ·  scripts/select_required_tests.py:58
Status
Unchanged. The pytest invocation is byte-identical — no timeout=, no -m "not slow". pytest.ini declares no markers and no test carries @pytest.mark.slow. Measured last round: test_nt_runner_collect.py is 16 passed in 1008.03s (16m 48s); the full suite is 131 passed in ~17m 49s, and preflight runs all 14 files.
Why it still matters
Nothing is failing — this is purely cost. The risk is second-order: a seventeen-minute "fast gate" invites --skip-tests as standing practice, which silently disables CAUSAL_INVARIANTS and reproduces the R4-3 condition by a different route. And with no timeout, a hung replay hangs preflight with no diagnostic.
Fix
Mark the end-to-end tests slow; run -m "not slow" in preflight and the full set at the pre-execution gate; pass timeout= to subprocess.run and treat expiry as BLOCKED with its own failure id.

A closing note on the arc. Round 1 found five criticals and three landed bypasses; this round found none of either, and the difference is not that I looked less hard — it is that the controls now measure rather than assert. Each round's residue has been the same defect in a new place: a check that reports a favourable result it did not compute. R6-1 is that defect one more time, in its mildest form yet, caught only because a neighbouring check happens to cover it. The convention that would retire the whole family is to make every safety check unconditional by default and require config to relax it, never to enable it. Both R4-1 and R6-1 were checks that config had to switch on; the validator's own get(..., "equal") default is the correct pattern already present in the codebase.
