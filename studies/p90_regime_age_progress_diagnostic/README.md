# P90 Edge by Regime Age × Realized Progress — how to run

Quick diagnostic. No model training, no entry policy, no exit work, no optimisation.
See `SPEC.md` for the frozen contract and `REPORT.md` for the answer.

## Run

```bash
# 1. cheapest gate first (free, deterministic)
python scripts/causal_lint.py --study studies/p90_regime_age_progress_diagnostic \
       --json studies/p90_regime_age_progress_diagnostic/audit/lint.json

# 2. deterministic contract tests (no store access, ~0.3s)
python -m pytest studies/p90_regime_age_progress_diagnostic/tests/ -q

# 3. the study, under the bounded runner
python scripts/run_bounded_study.py \
  --cmd "python -m studies.p90_regime_age_progress_diagnostic.run_study" \
  --timeout 7200 --stale-timeout 900 \
  --progress-file studies/p90_regime_age_progress_diagnostic/results/p90_events.parquet \
  --out-status studies/p90_regime_age_progress_diagnostic/results/run_status.json
```

`run_study.py` aborts on the first failed gate, so a clean exit means every gate in
`results/validation_report.json` passed.

## Phases

| Phase | What it does | Key output |
|---|---|---|
| 0 | Verifies the ORIGINAL eligibility contract against the accepted frozen training artifact; records the three discrepancies | `results/phase0_contract.json` |
| 1 | Builds arm populations A (model domain) and B (inherited >600 s) from the same code path | `results/population_lineage.json`, `results/p90_eligibility_base_rates.csv` |
| 2 | Simulates the three outcomes once per distinct `(regime_id, arm_ns)` event | `results/p90_events.parquet` |
| 3 | Aggregates into the frozen 40-cell grid, the velocity quartiles, and the A/B comparison | `results/primary_matrix.csv` ← **main deliverable** |
| 4 | Runs the gates and computes the D1–D5 verdict mechanically | `results/validation_report.json`, `results/summary.json` |

## Reading the tables

- **`primary_matrix.csv` is the main deliverable.** Rows are age buckets, columns are
  prevailing-regime running-MFE buckets, and each cell carries `n`, `p_flip_le_300s`,
  `p_confirm_before_1atr`, `median_return_at_confirm`, `median_eventual_mfe`.
- **Check `thin_cell` before reading any rate.** Cells with `n < 30` are retained with
  their N but are barred from every verdict test. The `120-240s` and `240-300s` rows are
  thin by a wide margin (see `SPEC.md` §2.5) — this is a finding, not a gap.
- **Two denominators, never interchanged.** `p_confirm_before_1atr` and `p_flip_le_*` are
  over all arms in the cell; `median_return_at_confirm`, `median_eventual_mfe` and every
  `p_mfe_ge_*` are over **confirmers only** and always appear next to `n_confirmed`.
- **`pct_age_ge_1800s`** flags the share of a cell armed beyond the model's training age
  ceiling (`SPEC.md` §1.2b). Anything in the `>900s` bucket is partly extrapolation.

## What this study does NOT do

No retraining or rescoring (no model artifact is loaded anywhere), no bucket-specific
models, no 5m-ATR normalisation, no exit study, no stop grid beyond the single accepted
1.00 ATR stop, and no tuning of any bucket edge or velocity cutoff. 2026 is sealed.
